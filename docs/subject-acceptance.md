# Сквозная проверка перед решением о версии 1.0

Из корня рабочей копии с установленными зависимостями запустите:

```powershell
node tools/verify-subject-acceptance.mjs
```

Для браузерной части нужен Windows с Microsoft Edge, для сборки — те же Node.js, pnpm и .NET SDK, что и для разработки. На чистой копии сначала установите зависимости интерфейса командой `pnpm --dir frontend/process-navigator-ui install --frozen-lockfile`.

Прогон последовательно собирает API и интерфейс, запускает клиентские тесты, проверяет мастер-данные и серверные сценарии, затем открывает изолированный браузер. В браузерном контуре проверяются импорт и публикация, детализация и документы, выполнение, расчёт сроков, обмен Excel, а также явное ожидание сообщения и таймера.

Рабочая база не нужна. Используются синтетические данные; браузер запускается с отдельным профилем, сервер — на локальном адресе с отдельным каталогом. Отчёт в `artifacts/subject-acceptance-*/report.json` содержит исходный коммит, признак локальных изменений, результаты этапов и имена журналов. Прогон останавливается при первой ошибке. Подробные отчёты мастер-данных и браузера указаны в журналах соответствующих этапов.

Успешный прогон подтверждает автоматическую регрессию, но не означает промышленную приёмку или выпуск 1.0. Четыре отложенных пункта 86–89 не входят в эту проверку.
