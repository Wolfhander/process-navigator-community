# Аналитика документов

В разделе «Аналитика → Документы и передачи» показан самостоятельный срез реестра документов и результатов. Для обновления используйте «Обновить реестр». Дата среза отображается над таблицей; фильтры списка процессов на неё не влияют.

Объекты упорядочены по числу записей источников и получателей. Это структурная частота использования в моделях, а не число отправленных документов. Несколько источников не порождают автоматически все возможные маршруты передачи.

Раскройте источники или получателей, чтобы увидеть процесс, этап, идентификатор, условие и заявленную версию. Кнопка названия открывает текущую схему процесса, не архивную редакцию.

Одинаковые нормализованные названия и псевдонимы разных ID отмечаются как возможные дубли. Программа не объединяет их и не считает совпадение доказательством ошибки. Версионные замечания поступают из реестра без самостоятельного толкования порядка номеров версий.

Поиск работает по ID, названию, псевдониму и названиям связанных процессов. CSV содержит все отфильтрованные объекты, дату реестра и полные исходные привязки в JSON-колонках; строки защищены от исполнения как формулы таблиц.

## Бумажные каналы и межсистемные переходы

Ниже реестра расположена самостоятельная проверка текущих схем. «Проверить передачи заново» получает новый срез. Источник данных и время обновления независимы от реестра выше. Поиск учитывает процесс, этапы, системы и ID документов; фильтр различает основной, параллельный и альтернативный бумажный канал, внесистемную работу, неуточнённую систему и межсистемный переход. На экране — по 100 записей; CSV содержит весь отфильтрованный набор.

Бумага сопоставляется с документом только при единственном совпадении названия и направления в привязках того же этапа. Иначе ID не подставляется наугад. Наличие бумажного канала не доказывает потерю документа и не делает альтернативный вариант обязательным.

Сравниваются системы выполнения непосредственно соединённых задач и ближайших задач по пути через шлюзы. Для каждой пары выбирается один кратчайший структурный путь, при равной длине — стабильный порядок ID; все альтернативные маршруты не перечисляются. Циклы завершаются без повторения одной пары. Условия ветвей, их совместимость и синхронизация не подтверждаются этим обходом. Через промежуточную задачу, событие или дочернюю модель обход не перескакивает.

Системы входа/выхода не подменяют систему работы. При пересечении наборов систем переход не объявляется установленным. Общий ID выхода/входа показан для проверки, но не подтверждает маршрут или соответствие версий. Ручной перенос, повторный ввод и автоматический обмен нельзя достоверно вывести только из соседства задач.

В блоке «Пути через шлюзы и ограничения проверки» доступны цепочки ID текущей страницы; в CSV — всех выбранных записей. Поиск учитывает ID промежуточного шлюза. При достижении 50 000 просмотренных связей на модель или 128 шлюзов в пути отчёт явно помечается неполным; предупреждение не исчезает при фильтрации записей.

Ограничения: вложенные модели пока не прослеживаются. Подтверждение способа переноса требует дополнительных данных. Соответственно пункты 69 и 70 дорожной карты не объявляются завершёнными. Контрольные сценарии: `master-data/transfers/process.json` и `gateway-cases.json`, проверяемые серверными тестами.
