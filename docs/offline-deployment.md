# Автономная поставка Process Navigator

Документ предназначен для передачи решения из предварительной зоны на сервер закрытого контура. Установщик не обращается в Интернет, не использует `npm`, NuGet и не требует установленного .NET Runtime.

## Что передать

Основной артефакт — один файл `ProcessNavigator-<версия>-win-x64-offline.zip` из раздела **Releases** закрытого репозитория GitHub. Рядом публикуется необязательный файл `.sha256`; его используют в предварительной зоне для проверки загрузки.

Архив содержит:

- самодостаточный ASP.NET Core сервер и уже собранный React-интерфейс;
- локальные библиотеки BPMN-редактора;
- начальный набор данных и организационную структуру;
- PowerShell-установщик и сценарий удаления;
- пользовательское руководство `USER-MANUAL.md`;
- исходники расширения 1С и документацию интеграции;
- `manifest.sha256` для проверки каждого файла после переноса.

На сервере не нужны Node.js, npm, Git, Visual Studio, .NET SDK или доступ к GitHub.

## Подготовка в зоне с Интернетом

1. Открыть закрытый репозиторий `Wolfhander/process-navigator` на GitHub.
2. Перейти в **Releases** и выбрать требуемую версию.
3. Скачать `ProcessNavigator-<версия>-win-x64-offline.zip` и соответствующий `.sha256`.
4. Проверить архив:

   ```powershell
   Get-FileHash .\ProcessNavigator-*-offline.zip -Algorithm SHA256
   Get-Content .\ProcessNavigator-*-offline.zip.sha256
   ```

5. Передать ZIP через установленный в организации шлюз/носитель. Файл `.sha256` можно передать вместе с ним, но для установки он не требуется: внутри ZIP есть подробный манифест.

## Требования к серверу закрытого контура

- Windows Server 2019/2022/2025 x64;
- PowerShell 5.1 или 7;
- локальный администратор на время установки;
- свободный TCP-порт (по умолчанию `5080`);
- DNS-имя и внутренний TLS reverse proxy рекомендуются для промышленной эксплуатации;
- место для приложения, файлов процессов и резервных копий в `C:\ProgramData\ProcessNavigator`.

## Установка

### Вариант 1. Запуск на отдельном компьютере без установки

1. Полностью распаковать ZIP в обычную папку, например `C:\ProcessNavigator`.
2. Дважды щёлкнуть `Start-ProcessNavigator.cmd`.
3. Подождать несколько секунд: браузер откроет `http://localhost:5080`.
4. Не закрывать окно `Process Navigator Server` во время работы. Для остановки закрыть это окно или запустить `Stop-Portable.cmd`.

В этом режиме все изменения сохраняются внутри `app\Data` в распакованной папке. Для резервной копии достаточно остановить программу и скопировать эту папку целиком.

### Вариант 2. Постоянная установка на сервер или рабочий компьютер

1. Скопировать ZIP на сервер и распаковать его в отдельный временный каталог.
2. Запустить `Install-ProcessNavigator.cmd`. Windows запросит права администратора, после чего программа установится и откроется автоматически.

Альтернативный ручной способ: запустить PowerShell **от имени администратора**, разрешить сценарии только для текущего окна и выполнить:

   ```powershell
   Set-ExecutionPolicy -Scope Process Bypass
   cd C:\Transfer\ProcessNavigator-<версия>-win-x64-offline
   .\install.ps1 -Port 5080 -OpenFirewall
   ```

3. Открыть `http://localhost:5080` на сервере или `http://имя-сервера:5080` с разрешённого рабочего места.
4. Проверить `http://имя-сервера:5080/api/health`: ответ должен содержать `healthy`.

Установщик проверяет контрольные суммы, размещает приложение, регистрирует запуск при старте Windows от имени `SYSTEM`, запускает сервер и выполняет проверку состояния.

## Обновление

Распаковать новый ZIP и повторно запустить `install.ps1` с тем же портом. Перед обновлением создаётся резервная копия рабочего каталога `Data`. Данные процессов, пользователи, назначения, комментарии, документы и ключи защиты не заменяются файлами новой версии.

Для очень большого репозитория документов резервное копирование можно выполнять штатными средствами организации и передать установщику `-SkipBackup`.

## Резервное копирование

Останавливать задание `ProcessNavigator`, затем копировать каталог:

`C:\ProgramData\ProcessNavigator\app\Data`

В нём находятся BPMN, контекст, версии, пользователи, оргструктура, назначения, исполнения, комментарии, документы и ключи шифрования. Восстановление выполняется только совместно с каталогом `Data\Keys`.

## Удаление

Из распакованного пакета выполнить:

```powershell
.\uninstall.ps1
```

По умолчанию рабочие данные остаются. Полное удаление выполняется явно: `.\uninstall.ps1 -RemoveData`.

## Промышленный контур и 1С

До подключения к реальным базам решение работает в демонстрационном режиме. Целевая схема — расширение 1С:ERP как точка входа и внутренний Process Navigator как веб-сервис. 1С:ERP, PLM, ЗУП, Управление холдингом/MDM и КОМПАС-3D остаются владельцами прикладных данных; BPMN, контекст процессов и версии принадлежат Process Navigator.

Перед промышленным запуском ИТ-служба должна дополнительно настроить HTTPS, резервное копирование, антивирусные исключения для каталога данных, журналирование, сервисную учётную запись вместо `SYSTEM` при необходимости и регламент обновлений.

## Как сформировать пакет без GitHub Actions

На компьютере сборки с Интернетом, .NET SDK 9 и Node.js 22:

```powershell
.\tools\build-offline-release.ps1 -Version 0.2.0-preview.2
```

Готовый ZIP и его SHA256 появятся в `artifacts`. Все зависимости скачиваются только во время этой сборки, но не на корпоративном сервере.
