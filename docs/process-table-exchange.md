# Табличный обмен процессами

## Сверка исходного описания

Колонка «Проверять маршрут» принимает «Да», «Нет» или пустое значение (выключено). При включении нужны минимум два разных элемента. Порядок ID в ячейке «Элементы схемы ID» задаёт последовательность проверки: ищется направленный путь от каждого элемента к следующему, в том числе через промежуточные блоки. Условия и обязательность прохождения не доказываются. Старые книги без колонки сохраняют настройку существующих пунктов по их ID; новые пункты получают выключенную проверку. Замечания о маршруте видны после импорта в проверке процесса и реестре.

Лист «Сверка» переносит пункты паспорта отдельно от фактов и вопросов шагов. Заголовки находятся в строке 3, данные начинаются со строки 4: ID процесса, уникальный внутри процесса ID пункта, содержание, источник, место и элементы схемы ID. Несколько элементов разделяются ` | `. На процесс допускается 100 пунктов, на пункт — 20 элементов. Содержание и источник обязательны.

Наличие листа заменяет пункты всех процессов книги; пустой лист очищает их. Отсутствие листа оставляет прежние пункты. Ошибки и изменения видны до записи. Неизвестный элемент или пустая привязка дают предупреждение, но не мешают сохранить пункт для дальнейшей сверки. При подтверждённом сопоставлении переименованного шага ссылки также приводятся к сохранённому ID. Привязка не означает подтверждение смысловой правильности процесса.

## Источники и вопросы шагов

Лист «Основания» входит в экспорт и пустой шаблон. Строка 3 содержит заголовки, начиная со строки 4 заполняется по одной записи: ID процесса, ID шага, статус сведений, содержание, источник, место в источнике и автор. Статусы: «Факт», «Предположение», «Вопрос» (также принимаются fact/assumption/question). Для факта источник обязателен. До 20 записей на шаг. Ячейки сохраняются как текст, ссылки не запускаются.

Наличие листа означает полную замену оснований всех шагов книги, включая очистку шагов без строк. Отсутствие листа сохраняет существующие записи. Это позволяет загружать старые книги без потери сведений. Проверка показывает ошибки с координатами, предупреждения о вопросах и предположениях и различия перед записью. При переносе в другой контур организации и подразделения должны существовать и соответствовать ID книги: лист оснований не создаёт оргструктуру.

## Тип и способ выполнения действия

На листе «Шаги» после прежних 26 колонок добавлены пять: **Тип BPMN**, **Способ выполнения**, **Система выполнения**, **Инструкция**, **Исполнитель действия**. Общая колонка «Тип» остаётся `task` для рабочих действий: это сохраняет совместимость маршрутов. Подтип задаётся отдельно:

| Тип BPMN | Значение |
| --- | --- |
| task | Общее действие |
| manualTask | Ручная работа |
| userTask | Действие пользователя |
| serviceTask | Автоматическая обработка |
| sendTask | Отправка сообщения |
| receiveTask | Получение сообщения |
| businessRuleTask | Применение бизнес-правила |

Для событий и шлюзов «Тип BPMN» совпадает с общим типом. «Способ выполнения» принимает `manual`, `external`, `system` либо пустое значение. Он не подменяет подтип: действие пользователя в ERP и автоматическая обработка системой различаются своим BPMN-типом. Название системы и инструкция передаются отдельными полями; канал передачи сам по себе не меняет тип действия. Новые значения видны в предварительном сравнении.

«Исполнитель действия» принимает `human` (сотрудник) или `system` (информационная система). Это отдельное свойство от способа работы и подразделения. Например, кладовщик работает в ERP: исполнитель `human`, способ `system`, система `1С:ERP`. Для автоматического извещения той же ERP исполнитель — `system`. Ответственное подразделение остаётся в колонках оргпривязки дорожки. Для системного действия сотрудники фиксируют подтверждение результата вручную: отметка в навигаторе не запускает ERP.

Если колонка исполнителя отсутствует, прежнее значение сохраняется; совместимы книги с 26 и 30 колонками. Пустая новая ячейка снимает явное назначение, после чего userTask/manualTask определяются как работа сотрудника, serviceTask — как работа системы; для общего task исполнитель остаётся неуточнённым. Участие системы в канале не определяет исполнителя. Проверка предупредит о неназванной системе и противоречащем типу исполнителе; неизвестные значения блокируются до записи.

Старые книги без новых колонок сохраняют значения существующего шага. В новой книге пустые способ, система и инструкция означают очистку соответствующего поля; пустой подтип сохраняет прежний подтип существующего действия, а явное `task` возвращает общий вид. Для нового шага без подтипа используется `task`.

Таблица не переносит внутренний граф встроенного `subProcess`, параметры `callActivity` и специальные параметры исполнения внешнего движка. Изменение встроенного подпроцесса или вызова через таблицу блокируется, включая старые книги, чтобы не потерять содержимое. Для таких изменений используйте исходный BPMN и редактор схем. Связанные процессы через обычный шаг и «Связанный процесс ID» продолжают поддерживаться.

Проверка разработчика: после сборки API выполнить `python tools/verify-task-type-roundtrip.py`. Проверка создаёт отдельный временный каталог и локальный сервер, прогоняет обмен и завершает сервер; рабочие процессы не меняются.

## Назначение

Табличный обмен нужен для массового описания и проверки процессов без ручного рисования каждого блока. Одна книга Excel должна поддерживать два направления:

1. **Таблица → Process Navigator:** программа проверяет строки, показывает предварительный результат и формирует либо обновляет BPMN-черновики.
2. **Process Navigator → таблица:** программа выгружает паспорта, шаги, переходы, оргпривязки, ответственных, системы и каналы. После дополнения данных книгу можно загрузить обратно по устойчивым идентификаторам.

## Первая версия шаблона

Заполняемый шаблон доступен в окне **Импорт моделей → Таблица Excel**. В нём находятся листы:

- **Инструкция** — правила заполнения и повторной загрузки;
- **Процессы** — паспорта, уровни и родительские модели;
- **Шаги** — события, действия, шлюзы, последовательность, подразделения и ответственные;
- **Каналы** — информационные системы, почта, бумага, телефон и другие способы передачи;
- **Справочники** — действующие идентификаторы организаций, подразделений и допустимые значения.

В шаблон выгружен демонстрационный контур уровней 0–4. Жёлтые ячейки предназначены для ввода. Формулы в колонке «Статус заполнения» выделяют обязательные данные, которых не хватает.

## Выгрузка существующего процесса

На той же вкладке выберите процесс и нажмите **Выгрузить в Excel**. Переключатель **Включить все вложенные процессы** формирует либо одну модель, либо всю её ветвь детализации. В книгу попадают доступная пользователю редакция, паспорт, шаги и переходы, оргпривязки дорожек, назначенные сотрудники, системы и каналы. Лист «Справочники» при этом обновляется по текущей оргструктуре.

Выгрузка сохраняет устойчивые ID. Поэтому книгу можно дополнить, проверить и загрузить обратно: существующие ID обновят соответствующие черновики, новые ID создадут новые элементы. Пользователь без права на черновики получает опубликованные редакции; аналитик или администратор — актуальные черновики, когда они существуют.

## Правила сопоставления

- `ID процесса`, `ID шага` и `ID канала` нельзя менять при корректировке существующей модели.
- Новый объект получает новый уникальный ID из латинских букв, цифр, точки, дефиса или подчёркивания.
- Несколько значений в одной ячейке разделяются символом `|`.
- Следующие шаги и подписи переходов задаются в одинаковом порядке.
- Организация и подразделение выбираются по ID из справочника, поэтому переименование не разрывает привязку.
- Строки с отсутствующими обязательными полями не должны автоматически менять опубликованную модель.

## Что уже проверяет программа

После выбора заполненной книги команда **Проверить таблицу без загрузки** выполняет разбор на сервере, но ничего не записывает. В предварительном результате видны:

- новые процессы и процессы, идентификаторы которых уже есть в каталоге;
- количество процессов, шагов и каналов;
- количество добавленных, изменённых, удалённых и неизменённых шагов для каждой существующей модели;
- подробное сравнение «было → станет» по каждому изменённому полю паспорта, шага, перехода и канала;
- возможную смену технического ID, когда удалённый и новый шаг имеют одинаковые название и тип;
- отсутствующие обязательные листы, поля и технические идентификаторы;
- повторяющиеся ID, ошибочные ссылки на следующий, родительский или связанный процесс;
- неизвестные организации и подразделения либо их неверное сочетание;
- недопустимые типы элементов, каналов, режимов и направлений передачи;
- предупреждения о незаполненном результате действия, триггере процесса или оргпривязке.

Ошибки нужно исправить до создания черновиков. Предупреждения не блокируют импорт, но обозначают места, где описание пока неполное.

Если программа показывает **«Возможна смена технического ID»**, проверьте, действительно ли новый объект заменяет прежний. Установите флажок у предложенного сопоставления: при загрузке программа сохранит прежний ID, историю, контекст и положение блока, а ссылки из таблицы перенаправит автоматически. Если это действительно новый шаг, не подтверждайте сопоставление и отдельно подтвердите удаление прежнего.

Перед загрузкой отметьте процессы, которые требуется создать или обновить. По умолчанию выбраны все модели без ошибок; процессы с ошибками недоступны для выбора. Кнопки **Выбрать доступные** и **Снять выбор** помогают работать с большими книгами. Ошибки невыбранных процессов не мешают загрузить корректную часть книги, но общая ошибка структуры файла (например, отсутствующий обязательный лист) блокирует операцию целиком.

Если одна и та же часть большой книги загружается регулярно, в блоке **Наборы выбора** введите название и сохраните текущую отметку. При следующей проверке выберите набор и нажмите **Применить**. Программа выберет совпавшие корректные процессы, отдельно перечислит ID, которых больше нет в книге, и процессы, которые не выбраны из-за ошибок. Наборы хранятся на сервере отдельно для каждого пользователя; сохранение с тем же названием обновляет прежний набор.

## Создание и обновление черновиков

Если проверка не нашла ошибок, нажмите **Создать/обновить черновики**. Перед записью программа автоматически создаёт полную резервную копию репозитория и показывает имя её файла в результате операции.

- новая строка процесса создаёт новый BPMN-черновик;
- существующий ID заменяет только черновик этого процесса; опубликованная редакция остаётся неизменной;
- повторная загрузка той же книги обновляет те же устойчивые ID и не создаёт скрытые дубли;
- дорожки получают оргпривязки, а указанные сотрудники — назначения;
- открытый в редакторе либо уже отправленный на согласование черновик не перезаписывается;
- создаются или обновляются только отмеченные в предварительном просмотре процессы; остальные строки книги не затрагиваются;
- отсутствие ранее существовавшего шага в таблице трактуется как удаление; для каждого выбранного процесса такое удаление требуется подтвердить отдельным флажком;
- сервер повторно проверяет подтверждение удаления и отклоняет импорт, если оно не передано;
- подтверждённая смена ID применяется только к предложенной сервером паре «новый → прежний»; произвольное, неоднозначное или устаревшее сопоставление отклоняется;
- у неизменённых элементов сохраняются ручные координаты, размеры и маршруты переходов;
- новые элементы и элементы с изменённым типом или дорожкой получают автоматическое размещение;
- сведения, которых пока нет в таблице (например, инструкция и материалы этапа), сохраняются при обновлении существующего шага.

После успешной операции можно скачать CSV-протокол. Он содержит итог по каждому процессу, все найденные изменения по полям, применённые сопоставления ID, ошибки и предупреждения. Если результат нужно отменить, администратор может восстановить автоматически созданную резервную копию через настройки.

## История загрузок

После закрытия страницы импорта результат не теряется. Откройте **Настройки → История импорта из Excel**. Для каждой завершённой операции там указаны:

- дата и пользователь, выполнивший загрузку;
- имя исходной Excel-книги;
- количество процессов в книге, созданных, обновлённых и пропущенных моделей;
- применённые сопоставления технических ID;
- имя автоматической резервной копии;
- перечень затронутых процессов и повторная загрузка CSV-протокола.

Кнопка **Открыть протокол** показывает его на отдельной странице без скачивания. В верхней части расположена сводка по добавленным, изменённым и удалённым данным и сопоставлениям ID. Протокол можно отфильтровать по результату процесса, типу записи или произвольному тексту в названии процесса, шага, поля, прежнем и новом значении. Для защиты браузера одновременно показываются не более 1000 найденных строк; полный CSV остаётся доступен для скачивания.

Пользователь с системными правами видит блок **Хранение протоколов**. В нём задаются срок хранения в днях и максимальное количество записей; значение `0` отключает соответствующее ограничение. Политика автоматически применяется после очередного импорта. Кнопка **Очистить сейчас** применяет её немедленно, а **Удалить** у отдельной операции удаляет запись журнала вместе с её CSV после короткого подтверждения. Эти действия не удаляют созданные процессы и резервные копии.

Журнал и протоколы хранятся в локальном каталоге данных `Data/ImportReports`, включаются в последующие резервные копии и не публикуются в Git. Если запись журнала существует, но соответствующий CSV-файл был удалён, страница явно сообщает, что протокол недоступен.

## Дальнейшее развитие

Следующие дополнения табличного обмена будут определяться по результатам загрузки реальных книг: пакетное исправление повторяющихся замечаний, дополнительные поля предметного реестра и более крупные наборы данных.
