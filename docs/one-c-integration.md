# Интеграция с 1С:ERP

## Архитектура

Process Navigator обращается к HTTP-сервису 1С во внутренней сети. Браузер не соединяется с 1С напрямую: команда проверяется backend, отправляется адаптером и записывается в журнал аудита.

Если интеграция выключена, ERP-действия продолжают работать в демонстрационном режиме. Это позволяет разрабатывать процессы до публикации HTTP-сервиса в 1С.

## Настройка

СуперАдминистратор открывает «Интеграция 1С» и указывает:

- базовый URL информационной базы;
- путь проверки доступности;
- путь выполнения команд;
- технического пользователя HTTP-сервиса;
- пароль и тайм-аут.

Пароль защищается ASP.NET Core Data Protection и не возвращается в интерфейс. После сохранения следует выполнить проверку соединения.

## Контракт проверки

Process Navigator отправляет `GET` на настроенный путь. Любой ответ со статусом 2xx означает доступность сервиса.

## Контракт команды

На путь команд отправляется `POST` с JSON:

```json
{
  "processId": "purchase-materials",
  "processVersion": "0.3",
  "elementId": "Task_CreateRequest",
  "elementName": "Создать заявку на закупку",
  "actionId": "create-request",
  "actionName": "Создать заявку в ERP",
  "target": "Документ.ЗаявкаНаЗакупку",
  "instanceId": "optional-instance-id",
  "userId": "demo-employee"
}
```

Ожидаемый ответ 1С:

```json
{
  "success": true,
  "message": "Заявка создана",
  "externalReference": "Документ.ЗаявкаНаЗакупку:000000123"
}
```

Неуспешный HTTP-статус, тайм-аут или `success: false` фиксируются в журнале команды как ошибка. Произвольную команду из браузера отправить нельзя: действие предварительно сверяется с опубликованным контекстом BPMN-элемента.

## Требования к HTTP-сервису 1С

Сервис должен быть доступен серверу Process Navigator, принимать JSON в UTF-8 и использовать HTTPS либо изолированный доверенный сегмент сети. Техническому пользователю следует выдать только минимально необходимые права.
