# Process Navigator 0.2.0-preview.66-dev

Предварительный выпуск локального навигатора бизнес-процессов. В комплекте только синтетические учебные данные. Не предназначен для промышленного размещения без отдельного усиления безопасности.

## Основные возможности

- BPMN-просмотр и редактор, организационные дорожки, инструкции, входы/выходы и документы.
- Декомпозиция с раскрытием дочерних моделей, проверка структуры и границ детализации.
- XLSX-шаблон, предварительная проверка и сравнение импорта, экспорт и сохранение устойчивых ID.
- Прямой и обратный расчёт сроков, календари, сценарии, условия ветвей и ограниченные возвраты.
- Аналитика портфеля, личные сохранённые наблюдения и сравнение срезов, CSV.
- Проверка бумажных каналов, переходов через шлюзы и границы вложенных моделей; сверка версий конечных задач и отдельные вызовы одного подпроцесса.
- Встроенное руководство, история изменений и подробная дорожная карта.

## Проверки выпуска

313 серверных сценариев и 237 клиентских проверок прошли. Сервер и интерфейс собираются. Сквозная передача проверена настоящим загрузчиком BPMN до четвёртого уровня на изолированных мастер-данных.

## Важные ограничения

- Структурная связь не доказывает исполнимость условий ветвей, синхронизацию, фактическую передачу документа или повторный ввод.
- Ручной перенос и автоматический обмен требуют явного описания; интеграция с 1С не считается реализованным промышленным обменом.
- Неуказанная версия отличается от доказанного конфликта; неполный обход помечается явно.
- Демонстрационное переключение профилей не заменяет промышленную аутентификацию. Используйте локальный доступ.

## Запуск

Для исходного проекта используйте `Start-ProcessNavigator.cmd` и инструкцию README. Для автономного Windows-пакета распакуйте ZIP в отдельный пользовательский каталог, прочитайте `INSTALLATION.md` и запускайте включённый `Start-ProcessNavigator.cmd`; установка службы для переносного режима не требуется.

Рабочие данные не следует отправлять в публичный репозиторий. Перед обновлением сохраняйте отдельную резервную копию. Новые GitHub Releases публикуются только по явной просьбе владельца проекта, а не после каждого изменения.
