# Приёмка пункта 61: повторные проходы

Версия 0.2.0-preview.123-dev, 7 ноября 2026. Все входные данные синтетические и приняты как рабочий эталон разработки, не как норматив предприятия.

## Источники и воспроизведение

- Генератор tools/schedule-iterations-fixture.mjs создаёт только данные в памяти; браузерная проверка сохраняет их в собственный artifacts/core-flow-browser-*/Data.
- После сборки Release API и интерфейса: node tools/verify-core-flow-browser.mjs. Собственный сервер/браузер завершаются; рабочие данные и чужие окна не затрагиваются.
- Сервер: ScheduleIterationChecks, вместе с регрессиями прежних алгоритмов. Клиент: scheduleIterations.test.mjs.

## Принятые результаты

1. Строго вложенный эталон: исходная последовательность 8 ч; план внешнего/внутреннего дополнительных проходов 1/2 — 18 ч; предел 2/3 — 29 ч. Правка выполняется 6/12 раз; подготовка и финальная передача — один раз. Два раздельных участка не перемножаются.
2. В прямом расчёте от 09.11.2026 09:00 UTC разработка заканчивается 11.11 в 11:00 UTC; обратный проход восстанавливает исходный старт. Предел требует более раннего старта. Отдельный график исходной правки 17:00–18:00 применяется ко всем её клонам.
3. В браузерном эталоне старт 09:00 UTC+3; с двухчасовой приёмкой цепочка занимает 20 рабочих часов. Плановая/предельная таблицы имеют разные проходы; распределение внешнего числа 0/1 с массами 0,25/0,75 при внутреннем числе 2 даёт 12/20 ч вместе с приёмкой и среднее 18 номинальных часов.
4. Batch потребляет полный комплект после всех проходов производителя. PerPass сопоставляет шесть атомарных результатов с шестью проходами получателя по порядку. Несовпадение количеств или отсутствие режима отклоняется; результаты не становятся фактами доставки, подписями, новыми версиями или автоматически запущенными выполнениями.
5. Снимок содержит исходные модели/ID, правила, числа и распределения, отдельно план/предел и координаты вложенности. Временные ID не подменяют источники, диагностические ссылки и итоговые зависимости. Серверный архив воспроизводится без текущего каталога. CSV включает все строки, не только открытую страницу.
6. Пересечения, общие границы вложенности, внутренние явные/неявные AND, незаданные циклы, неверные распределения и превышение развёртки отклоняются. Выбранный тупик остаётся предварительным; исключённый получатель не ломает проверку календарей. Отдельный HTTP-запрос читает схемы для настройки без вычисления дат.

Итог: 436 клиентских тестов, 1010 серверных сценариев, 20 групп браузер/API. Успешны сборки интерфейса и Release API без предупреждений сборки API. Просмотрены снимки широкого/узкого экранов 1440/360 CSS-пикселей: текст переносится, таблицы прокручиваются локально. Параметры исключённого получателя сохраняются и воспроизводятся архивом, а не теряются при отсечении цепочки.

## Независимая проверка и исправления

Адресная проверка pavel-reviewer выявила три дефекта по трассировке: календари исключённого процесса, потерю исходного окончания и неявный AND. Основной агент исправил их и выполнил отдельные регрессии. Повторная проверка чтением не нашла новых существенных дефектов; она не заменяет исполняемые тесты. Локальная LLM не вызывалась: семантика/приёмка требуют основной модели, подсчёты и экспорт выполнены прямыми программами.

## Границы

Конечные участки с одним входом/выходом: 8 на процесс, 16 на цепочку, глубина 6, 0–50 дополнительных проходов, суммарно 10 000 узлов / 20 000 переходов на развёрнутую модель. До 8 распределений и 64 полных исходов, без усечения. Выбранное число внутренних проходов одинаково при каждом внешнем входе, а не независимо разыгрывается заново.

Межпроцессная модель сохраняет консервативный барьер полного завершения производителя, не находит оптимальный потоковый график. Для составных комплектов и их частей допускается только Batch. Вероятностные XOR и прежний простой повтор не совмещаются с новым режимом; прежние снимки продолжают работать прежним алгоритмом.

Детализация связанного подпроцесса открывается по ссылке; повторяется явно заданный норматив родительского шага. Автоматическое суммирование дочерних нормативов не выполняется. Это ограниченное планирование по модели, не универсальное исполнение BPMN, не прогноз обученной модели и не гарантия срока. Сообщения/таймеры остаются в пункте 96.
