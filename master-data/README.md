# Эталонные данные и шаблоны

Все организации, документы и процессы здесь синтетические. Они не содержат данных предприятия и не подтверждают фактическое подписание документов.

## Состав набора v1

- `v1/spec.json` — исходные параметры, ожидаемые количества и прямые/обратные календарные расчёты.
- `v1/reference/Data` — пять связанных процессов уровней 0–4, три организации, шесть подразделений и материал версии 1.0. Один подпроцесс используется повторно.
- `v1/documents/MD-001.md` — заполненный пример входного документа.
- `v1/documents/process-passport-template.md` — заполняемый паспорт для последующей реальной работы.
- `v1/reference/instruction.html` — пример полной инструкции с вложенными процессами.
- `v1/coverage.json` — связь проверок с пунктами дорожной карты и оставшимися ограничениями.

## Повторная проверка

В корне репозитория выполните `node tools/verify-master-data.mjs`. Нужны Node.js 24, .NET 9 и восстановленные зависимости проекта. Локальная модель для этих детерминированных проверок не нужна.

Каждый запуск создаёт отдельную папку `artifacts/master-data/<дата-время>-<номер>`. В ней находятся протокол, контрольные суммы входов, журналы и книги, сформированные штатным экспортом программы:

- `master-processes.xlsx` — пять связанных моделей;
- `master-large-3000.xlsx` — нагрузочный пример на 3000 действий.

Книги проверяются обратным импортом без изменения рабочего контура. Отображение и пересчёт формул в Microsoft Excel этим запуском не проверяются. Последний опубликованный протокол находится в `verification.json`; это снимок результата, а не проверка текущего компьютера.

## Использование для реальной работы

Копируйте нужный образец отдельно. Замените вымышленные сведения, согласуйте идентификаторы организаций, подразделений, процессов и документов. Сохраняйте связи и версии; совпадение названий не означает совпадение идентификаторов. Не копируйте весь каталог Data поверх рабочих данных.

В реестре специально различаются явная передача документа по ID и текстовые упоминания входов/результатов: упоминание само по себе не доказывает передачу. Требование статуса «Подписан» — правило, а не доказательство подписи.

Автоматический успех не закрывает приёмку предприятия, проверку экранов, печати и сторонних форматов. Эти ограничения сохраняются в протоколе и дорожной карте. Изменения рабочего контура автоматически сюда не попадают и в GitHub не отправляются.
