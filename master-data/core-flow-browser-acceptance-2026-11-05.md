## Изоляция и результаты

Инструмент создаёт artifacts/core-flow-browser-* и собственные Data/wwwroot/профиль Edge. API слушает динамический порт только 127.0.0.1. Не подключается к уже запущенным серверам или браузерам и не завершает их. Созданные одноразовые процессы закрываются в finally; артефакты оставлены для диагностики.

Проверены семь групп:

1. В форме импорта CDP загружает реальные .bpmn/.json. Через кнопку открывается SVG нового черновика. Входные Published/9.9 нормализуются в Draft/0.1; до публикации нет BPMN в корне Data.
2. Повторный импорт получает 409, импорт исполнителем — 403. Оба файла черновика после отказов побайтово неизменны.
3. Без JSON тоже создаётся читаемый черновик 0.1 с hasDraft; повторная загрузка не перезаписывает его.
4. API-валидация: 0 критических ошибок, canPublish=true. Браузер проходит штатные этапы согласования и обязательную проверку; публикация отображается действующей версией. Статус не меняется прямой записью файла тестом.
5. Через интерфейс создаётся выполнение и последовательно начинаются/завершаются все четыре действия. API подтверждает Completed всех шагов и экземпляра.
6. Навигация в каталог и полное обновление страницы сохраняют нужный раздел.
7. В браузере запускаются оба направления расчёта. Нормы: 4 часа, понедельник 09.11.2026, 09:00–13:00 UTC+3. Проверены и отдельный API-вызов, и тела обоих реальных ответов браузеру; обратный расчёт возвращает исходную дату начала. Runtime-ошибок браузера нет.

В report.json сохраняются группы, ответы по HTTP-статусам, результат, а при сбое — этап и ограниченный текст учебной страницы. schedule.png визуально просмотрен. Это настоящий собранный интерфейс с API, не SSR-заглушка. Кнопки и SVG нажимаются событиями мыши CDP; select/input заполняются через штатные DOM-события React. Клавиатура отдельно проверяется сценарием шага 79.

## Обнаруженное исправление

Одиночный импорт ранее записывал Draft в корень Data, но дальнейшее чтение искало его в Data/Drafts: «Открыть процесс» возвращало 404. Новые импорты используют правильный путь, нормализуют статус/версию и проверяют занятость ID как действующей моделью, так и черновиком. Старые файлы автоматически не преобразуются; это не миграция фонда.

Пределы: один линейный маршрут в Edge/Windows, без обещания исчерпывающего покрытия шлюзов, таймеров, вложенности или всех браузеров. Специализированные проверки остаются отдельными. Local AI Worker не использовался: факты проверяются детерминированными событиями, HTTP и сравнением файлов.

Итоговый прогон: 398 клиентских тестов, 799 серверных сценариев, обе сборки успешны; финальный сквозной прогон — PASS, семь групп. Логи находятся в artifacts/core-flow-client-checks.log, core-flow-server-checks.log и core-flow-*-build.log. Изменения опубликованы обычным коммитом, без отдельного GitHub Release.
