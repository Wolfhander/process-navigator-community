# Контроль передач

`gateway-cases.json` хранит отдельные маршруты через шлюзы: прямую развилку, схождение с циклом и выбор стабильного пути равной длины. Серверные проверки сравнивают точную последовательность ID. Дополнительные сценарии проверяют остановку на задаче/событии, оборванную связь, отмену запроса и ограничения обхода.

Режим `node tools/verify-transfer-analytics.mjs --gateway` добавляет шлюз между PLM и ERP в изолированной тестовой копии, затем проверяет точную цепочку ID через HTTP. Требования к адресу и каталогу те же, что для базовой проверки ниже.

`process.json` — синтетическая модель входных данных сервиса аналитики, а не готовый BPMN-шаблон предприятия. Специально содержит неуточнённый этап, бумажную альтернативу без документа и разные версии чертежа. Удалять эти неоднозначности ради «зелёной» проверки нельзя.

Ожидаются шесть признаков: основной, параллельный и альтернативный бумажные каналы; работа по телефону; неуточнённая система; прямой переход PLM → ERP с общим ID `drawing`. Разные версии не должны исчезнуть из реестра и не должны подтверждаться совпадением ID.

Проверка в `TransferAnalyticsChecks` дополнительно меняет модель в памяти: одинаковые системы, входная система вместо рабочей, устаревшее поле системы, шлюз, неоднозначные одинаковые названия, пересечение наборов систем и оборванная связь.

`tools/verify-transfer-analytics.mjs` рассчитан только на отдельный тестовый сервер `127.0.0.1:5087`, использующий `artifacts/master-acceptance/Data`. Он проверяет состав тестового каталога перед созданием временных BPMN/context-файлов. Не запускайте его против пользовательского сервера. Результат сохраняется в игнорируемый `transfer-actual.json`; исходные процессы приложения он не меняет.
