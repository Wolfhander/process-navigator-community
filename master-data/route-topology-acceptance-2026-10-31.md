# Приёмка структурных маршрутов — 31 октября 2026

Пункты 15 и 16. Вымышленные контрольные графы считаются рабочими мастер-данными: route-topology-fixture.json. Проверки используют файл напрямую, а не только заранее записанные ожидаемые ответы.

## Критерии

- Прямая, вложенная и совмещённая AND-пара; два самостоятельных потока между одинаковыми шлюзами учитываются отдельно.
- Обход объединения, отдельные завершения, внешние входы, смешанные происхождения и альтернативы перед AND не получают ложного подтверждения. Нестандартная пара вызывает рекомендацию, не автоматический запрет.
- Компоненты повторов ищутся итеративно, включая независимые компоненты и петли; проверена глубина 10000 элементов. Показанные ID — множество, не вымышленный порядок маршрута.
- Подписанный выход XOR — структурное свидетельство, не доказательство истинности условия. Без него сохраняется строгая блокировка приложения. Расчёт числа итераций и длительности остаётся пунктом 61.
- Неверные ID/ссылки, предел 10000 элементов / 20000 потоков, бюджет 200000 операций и отмена проверены отдельно. Ограниченный анализ явно обозначен.
- Настоящий ProcessValidationService возвращает топологию; сходящийся XOR с двумя входами/одним выходом не требует двух выходов. Разветвляющийся XOR по-прежнему требует подписи альтернатив.
- Сводка встроена в существующую проверку публикации: переходы к ID, максимум 100 пар/компонент, до 50 ID внутри компоненты с полными количествами. Старый ответ без топологии допустим; React экранирует текст.

## Воспроизведение

Из корня: dotnet run --project backend/ProcessNavigator.Checks -c Release.
Из frontend/process-navigator-ui: node --test tests/*.test.mjs; pnpm build.
Подробные случаи: backend/ProcessNavigator.Checks/RouteTopologyChecks.cs, frontend/process-navigator-ui/tests/routeTopology.test.mjs.

C#: 683 сценария, клиент: 334 проверки — успешно. Четыре графа из сохранённого JSON прочитаны проверками напрямую; дополнительные случаи заданы в C#. Клиентская сборка успешна. Отдельная HTTP/визуальная проверка браузером в этом протоколе не заявляется. Это не формальная проверка soundness и не симулятор токенов.

Основа семантики: [OMG BPMN 2.0.2, 13.4.1–13.4.2](https://www.omg.org/spec/BPMN/2.0.2/PDF). XOR-объединение не выполняет AND-синхронизацию.
