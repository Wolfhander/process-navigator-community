# Изоляция ID процессов — приёмка исправления .118-dev

## Согласованные мастер-данные

Источник геометрии: штатная demo-showcase-l4-drawing.bpmn. ProcessIdentityChecks.cs создаёт в отдельной временной установке модели legacy, second, third, created, generated, occupied и other. Общий тестовый контекст содержит учебного владельца и редакцию 0.1. Статус Approved в сервисном тесте — специально подготовленная фикстура, не способ обхода прав в приложении.

## Закрытые критерии

1. Старый __missing__.bpmn найден только по своему XML ID; неизвестный ID возвращает отсутствие, а не чужой файл.
2. Импорт и публикация second и third создают независимые файлы. Повторный ID отклоняется, исходные байты legacy не меняются.
3. Создание пустой модели, генерация табличного черновика и получение списка версий работают после публикации.
4. Чтение/удаление неизвестного ID и удаление отдельного черновика не затрагивают опубликованные соседние модели.
5. Посторонний файл на месте новой публикации сохраняется; одобренный черновик при отказе не изменяется.
6. Неизвестный черновик не получает общий источник; путь вместо ID отклоняется.
7. Живой браузер/API проходит первый импорт, согласование и публикацию, затем второй импорт, согласование и публикацию. Оба ID повторно открываются. Неизвестные запросы BPMN/удаления получают 404; специальное конечное событие второй модели по-прежнему блокирует исполнение.

## Проверки и границы

24 новых серверных проверки; полный прогон — 860 сценариев. Клиент — 414 тестов. Сквозной браузер/API — 13 групп. Артефакты прогона находятся в локальной исключённой из Git папке artifacts; рабочие данные пользователя не меняются.

В промежуточных запусках пойманы 503 при чтении workflow и instances одновременно с записью. В тестовом API-поллинге добавлено до трёх повторов только диагностического GET на временный 503; каждый случай сохраняется в transientReads отчёта. Бизнес-записи не повторяются. Окончательный изолированный прогон завершился успешно. Устойчивость конкурентного чтения в самом приложении не считается исправленной данным пакетом.

Миграция старых файлов не выполняется. Дубли ID в разных вручную подложенных XML и транзакционная публикация нескольких файлов одновременно не решаются этим исправлением. Автоматически удалять, переименовывать или перезаписывать занятые файлы нельзя. Детерминированные исходники и тесты использованы вместо LLM-делегирования: анализ идентичности и защиты данных требует прямой проверки.
