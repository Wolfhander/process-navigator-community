# Приёмка шага 93: происхождение сведений

Дата: 2026-11-05. Источник: v1/documents/TRACE-001.md. Параметры: provenance-fixture.json. Сведения и организации вымышлены; источник намеренно создан как мастер-шаблон приёмки, не как реальный производственный регламент.

## Воспроизведение из корня

```powershell
dotnet build backend/ProcessNavigator.Api -c Release --no-restore
pnpm --dir frontend/process-navigator-ui build
node tools/verify-provenance-http.mjs
node tools/verify-core-flow-browser.mjs
```

Оба инструмента создают новые отдельные каталоги в artifacts, синтетические Data и собственный API на динамическом порту 127.0.0.1. Браузерный тест использует собственный скрытый Edge и профиль. Рабочие установки не используются, чужие процессы не завершаются. Созданные серверы/браузер закрываются автоматически; отчёты остаются в artifacts. Зависимости и Edge должны быть установлены заранее.

## Результаты

- HTTP-прогон сохраняет отдельные основания одного оригинала для процесса, действия, исходящего перехода и документа реестра. Содержание, место и справочный автор проходят нормализацию и сохраняются; профиль загрузившего берётся сервером, не из поля автора.
- Сверка неизменной цели даёт matches. Повторная загрузка того же файла с той же привязкой идемпотентна.
- Несуществующий переход, сочетание перехода с этапом, неизвестный статус, пустое содержание и превышение длины координат отклонены. Неизвестное поле execute в цитате не исполняется и отклоняется десериализацией.
- Без новых полей материал продолжает читаться; удаление новых необязательных полей из метаданных старого формата не меняет результат сверки/отпечаток.
- Подмена оригинала при прежнем размере обнаруживается SHA-256: unavailable, скачивание отклоняется. Отсутствие файла даёт ошибку и unreadable=1, не matches. После восстановления байтов файл снова пригоден для сверки.
- При изменении модели исходник остаётся исторически привязанным; сама модель не меняется при загрузке или проверке материала.
- Исполнителю отказано в загрузке/проверке черновых оригиналов; черновая запись не выдаётся в его списке.
- В настоящем браузере создаётся основание перехода Task_Model → Task_RegisterPlm, берётся соответствующее заявление из раздела 2 TRACE-001, сохраняется и отображается с координатой и автором. Сверка показывает SHA-256; переход к модели фокусирует стрелку. provenance.png визуально просмотрен.

Прямой HTTP-прогон включает 37 запросов-проверок; сквозной браузерный маршрут — 10 групп вместе с ранее принятыми импортом/планом/исполнением.

## Границы

Это происхождение заявления по сохранённому оригиналу, не проверка истинности. Файл, автор сведений и субъект загрузки различаются. Внешние URL и пути не запрашиваются, документы не исполняются и автоматически не анализируются. Текстовые основания шагов не преобразуются в файловые связи автоматически. Файловые основания хранятся отдельно от BPMN/XLSX и входят в существующее резервирование SourceMaterials. История публикаций схемы и история ручной проверки шага — другие механизмы.

Модель/оригинал не меняются при сверке. Старый формат без edge/citation работает; новая версия добавляет только необязательные поля, миграции нет. Старые сборки не показывают новые сведения. Local AI Worker не вызывался: проверка байтов, идентификаторов, прав и DOM выполняется детерминированно.
